# Архитектура Base AI Platform

## Текущее состояние

Рабочее приложение сейчас находится в одном файле `ai-platforms.html`, где объединены:

- HTML-разметка интерфейса;
- CSS-стили;
- бизнес-логика на JavaScript;
- локальное хранилище и миграции данных;
- шифрование секретов;
- каталог стартовых AI-платформ;
- обработчики интерфейса, импорт и экспорт.

`index.html` остаётся входной точкой и перенаправляет пользователя на `ai-platforms.html`.

## Целевая структура первого этапа

```text
/
├── index.html
├── ai-platforms.html
├── assets/
│   ├── app.css
│   └── app.js
└── docs/
    └── architecture.md
```

На первом безопасном шаге CSS вынесен в `assets/app.css` без изменения правил оформления.

## Почему рефакторинг делается поэтапно

`ai-platforms.html` содержит одновременно интерфейс, данные и критичную логику сейфа. Одновременное дробление большого файла на несколько модулей повышает риск незаметной регрессии: можно нарушить порядок объявления функций, стартовую инициализацию, работу импорта/экспорта или шифрования.

Поэтому рекомендуемый порядок такой:

1. Вынести стили без изменения поведения.
2. Вынести JavaScript как единый `assets/app.js`, сохранив исходный порядок кода.
3. Проверить основные пользовательские сценарии.
4. Только после этого разделять JavaScript по ответственности.

## Следующая целевая структура JavaScript

После стабилизации внешнего `app.js`:

```text
assets/js/
├── config.js        # константы и справочники
├── utils.js         # общие утилиты
├── storage.js       # localStorage, импорт/экспорт, миграции
├── vault.js         # PBKDF2/AES-GCM и мастер-пароль
├── platforms.js     # модель платформ и расчёты
├── payments.js      # способы оплаты
├── ui.js            # рендеринг, модальные окна, формы
├── events.js        # обработчики DOM-событий
├── seed.js          # стартовый каталог платформ
└── bootstrap.js     # запуск приложения
```

На этом этапе сборщик, npm, React или другой фреймворк не требуются. Цель — сохранить простой статический деплой GitHub Pages и одновременно снизить связанность кода.

## Обязательные проверки перед подключением внешних файлов

- старт страницы и загрузка каталога;
- поиск, фильтры и сортировка;
- создание и редактирование платформы;
- удаление и Undo;
- создание/разблокировка/блокировка сейфа;
- чтение и сохранение зашифрованных секретов;
- смена мастер-пароля;
- импорт полного backup;
- экспорт полного и публичного backup;
- управление картами и сервисами оплаты;
- светлая/тёмная тема;
- мобильная раскладка.

## Принцип дальнейшей разработки

Каждое функциональное изменение должно идти отдельным небольшим PR после структурного рефакторинга. Это позволит независимо тестировать будущие функции: dashboard «Требуют внимания», частоту использования сервисов, оценку окупаемости подписок, облачную синхронизацию и AI-ассистента.
