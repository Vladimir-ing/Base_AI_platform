# Архитектура Base AI Platform

## Общая схема

Base AI Platform — статическое браузерное приложение на HTML, CSS и JavaScript. Интерфейс публикуется через GitHub Pages, а серверные функции предоставляет Supabase.

```text
Пользователь
  └─ GitHub Pages
      ├─ Supabase Auth ── проверка сессии
      ├─ Supabase Postgres ── персональная запись user_vaults
      └─ Supabase Edge Function ── безопасный вызов OpenAI
```

## Компоненты

| Компонент | Ответственность |
|---|---|
| `index.html` | Перенаправляет на защищённое приложение |
| `login.html` + `assets/auth-page.js` | Вход, регистрация, восстановление и обновление пароля |
| `ai-platforms.html` | Разметка основного интерфейса и модальных окон |
| `assets/route-guard.js` | Проверяет пользователя до загрузки бизнес-логики |
| `assets/app.js` | Каталог, платежи, сейф, аналитика, помощник, импорт/экспорт и cloud sync |
| `assets/app.css` | Основной дизайн и адаптивная раскладка |
| `assets/auth.css` | Экран авторизации, состояние маршрута и индикатор облака |
| `public.user_vaults` | Одна JSON-запись на пользователя с RLS-защитой |
| `ai-base-assistant` | Edge Function, проверяющая JWT и вызывающая OpenAI без передачи ключа браузеру |
| `account-access` | Возвращает пользователю его эффективный режим, тариф и лимиты |
| `admin-dashboard` | Возвращает только администратору агрегаты и список аккаунтов без содержимого vault |
| `public.user_access` | Серверные роли, trial и состояние будущей подписки |
| `public.billing_plans` | Цены и лимиты Basic / Pro / Max |
| `public.product_settings` | Переключатель бесплатного запуска и будущей оплаты |
| `public.llm_usage_events` | Технический учёт запросов и токенов без текста сообщений |

## Загрузка приложения

1. Браузер открывает `ai-platforms.html`.
2. Создаётся Supabase-клиент с URL проекта и publishable key.
3. Route guard проверяет текущего пользователя через Supabase Auth.
4. При действующей сессии загружается `assets/app.js`; иначе пользователь перенаправляется на `login.html`.
5. Приложение читает локальный кэш и запускает синхронизацию с `user_vaults`.

## Модель хранения

- Полное состояние приложения хранится в JSON `payload`.
- В Postgres для каждого `auth.users.id` существует не более одной строки.
- Пароли, API-ключи и приватные заметки шифруются до записи в `localStorage` и Supabase.
- Обычные поля каталога и тарифов остаются открытыми внутри персональной записи.
- Изменения сначала сохраняются локально, затем отправляются в облако с задержкой 800 мс.
- При временной ошибке сети локальная версия остаётся рабочей и повторно синхронизируется после восстановления соединения.

## Граница безопасности

- В публичном JavaScript допустим только Supabase publishable key.
- Secret key, service-role key и OpenAI API key не должны попадать в репозиторий или браузер.
- RLS ограничивает чтение, добавление и изменение строки условием `auth.uid() = user_id`.
- Браузер не имеет права удалять строки `user_vaults`.
- Edge Function проверяет пользовательский JWT на сервере.
- Роль администратора проверяется серверно и не берётся из редактируемых пользователем метаданных.
- Бесплатный ранний доступ включён отдельной серверной настройкой; будущие лимиты уже защищены RLS.
- В LLM не отправляются логины, секреты и приватные заметки.

## Разработка и проверка

Изменения выпускаются небольшими PR. Перед публикацией необходимо проверить:

- вход, регистрацию, выход и восстановление пароля;
- защиту маршрута без сессии;
- загрузку и сохранение cloud vault;
- поиск, фильтры, добавление, редактирование и удаление платформ;
- создание, разблокировку и автоматическую блокировку сейфа;
- импорт и оба вида экспорта;
- расчёты подписок, платежные связи и сравнение платформ;
- удалённый и локальный режим помощника;
- мобильную раскладку, тёмную и светлую темы.
