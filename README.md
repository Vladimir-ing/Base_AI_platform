# База AI-платформ

Личный каталог AI-сервисов: назначение, рабочие приёмы, ссылки, доступы, тарифы, даты списаний и способы оплаты — в одном интерфейсе.

[Открыть приложение](https://vladimir-ing.github.io/Base_AI_platform/) · [Архитектура](docs/architecture.md) · [Авторизация](docs/auth.md) · [Облачная синхронизация](docs/cloud-sync.md) · [LLM-помощник](docs/llm-backend.md)

## Быстрый старт

1. Откройте [сайт](https://vladimir-ing.github.io/Base_AI_platform/) и войдите в аккаунт.
2. Нажмите **«? Инструкция»** в верхней панели — там есть короткая памятка по основным действиям.
3. Найдите нужный сервис или нажмите **«+ Платформа»**.
4. Откройте карточку → **«Редактировать»** и заполните статус, ссылки, тариф, оплату и заметки.
5. Если нужны пароли или API-ключи, нажмите **«Создать сейф»** и задайте мастер-пароль.
6. После изменений дождитесь статуса **«Сохранено»**.
7. Периодически делайте **⋯ → Экспорт бэкапа** как независимую резервную копию.

## Как пользоваться сайтом

### Найти сервис

- Строка поиска ищет по названию, назначению, приёмам, тегам, логину и способу оплаты.
- Категории, статусы и фильтр оплаты сужают список.
- Карточки статистики и расходов пересчитываются по текущей выборке.
- Клик по плитке открывает полную карточку, а **⇗** сразу ведёт на сайт или в личный кабинет.

Горячие клавиши: `/` — перейти в поиск, `Esc` — закрыть открытую карточку или окно.

### Добавить или изменить платформу

Нажмите **«+ Платформа»** или плитку добавления в конце списка. В карточке можно хранить:

- назначение, сильные стороны, приёмы и теги;
- статус регистрации и частоту использования;
- ссылки на сайт, личный кабинет и страницу тарифа;
- логин и способ авторизации;
- тариф, цену, валюту, период и дату продления;
- способ оплаты и дату последней проверки цены;
- пароль, API-ключ и приватную заметку — только внутри зашифрованного сейфа.

Удаление требует подтверждения. В течение 12 секунд его можно отменить кнопкой **«Вернуть»**.

### Следить за подписками

В верхней части страницы находятся:

- **сводка** — количество платформ, активные подписки, расходы и ближайшее списание;
- **требуют внимания** — записи, в которых нужно проверить цену, продление или заполнение;
- **экономика подписок** — регулярные расходы и потенциальная экономия.

Годовые тарифы пересчитываются в среднем на месяц. Разовые платежи не входят в месячную сумму, а разные валюты показываются отдельно.

### Указать способ оплаты

Откройте **⋯ → Оплата: сервисы и карты…** или добавьте способ прямо в карточке платформы.

| Тип | Когда использовать |
|---|---|
| Сервис оплаты | Посредник, виртуальная карта или сервис конвертации со своим сайтом, логином, тарифом и заметками |
| Карта или счёт | Простая метка: например, «Карта Т-Банк» или «PayPal» |

Номер карты, срок действия, CVV и коды из СМС сохранять нельзя. Для учёта достаточно названия способа оплаты.

### Сравнить платформы

Нажмите **«Сравнить»**, выберите несколько сервисов и получите таблицу по назначению, возможностям, тарифам, оценкам и вашим заметкам. Это удобно перед продлением подписки или выбором инструмента под задачу.

### Использовать помощника

Кнопка **«Помощник»** открывает AI-анализ базы. Можно спросить, например:

- чем лучше сделать презентацию;
- какие подписки можно отключить;
- какие сервисы дублируют друг друга;
- какой инструмент подходит для конкретной задачи.

В LLM отправляется только рабочее описание каталога и тарифные данные. Логины, пароли, API-ключи, приватные заметки и содержимое сейфа не отправляются.

## Сейф и мастер-пароль

Пароли, API-ключи и приватные заметки шифруются в браузере с помощью AES-256-GCM. Ключ создаётся из мастер-пароля через PBKDF2 и не сохраняется.

- Сейф автоматически закрывается через 10 минут без действий и после перезагрузки страницы.
- Показанный пароль скрывается через 15 секунд.
- Скопированный секрет удаляется из буфера обмена через 30 секунд, если браузер разрешает это действие.
- Мастер-пароль восстановить невозможно. Его нужно сохранить отдельно в менеджере паролей.

Обычные поля каталога — названия, описания, тарифы и статусы — не шифруются.

## Облачная синхронизация

После входа данные хранятся в двух местах:

1. локальный кэш браузера для быстрого запуска и временной работы без сети;
2. персональная запись в Supabase для использования базы на разных устройствах.

| Статус | Значение |
|---|---|
| **Сохранено** | Последние изменения записаны в облако |
| **Синхронизация…** | Идёт загрузка или сохранение |
| **Только локально** | Сети нет или облако временно недоступно; изменения остаются в браузере и будут отправлены позднее |

При первом входе существующая локальная база переносится в облако, если облачной записи ещё нет. На другом устройстве достаточно войти в тот же аккаунт.

Доступ к записи ограничен RLS-политиками Supabase: авторизованный пользователь может читать и изменять только собственную строку. В браузере используется publishable key; secret/service-role key в проект не добавляется.

## Бэкапы и восстановление

Облачная синхронизация не заменяет независимый бэкап.

| Действие | Результат |
|---|---|
| **Экспорт бэкапа** | Полный JSON со всей базой; секреты внутри остаются зашифрованными |
| **Экспорт без доступов** | Каталог без логинов, секретов и платёжных привязок — подходит для передачи другому человеку |
| **Импорт из файла** | Восстановление или объединение с текущей базой |

При импорте совпадающие платформы можно заменить, пропустить или добавить как новые. После импорта дождитесь статуса **«Сохранено»**.

## Устройство проекта

```text
/
├── index.html                     # входная точка GitHub Pages
├── login.html                     # вход, регистрация и восстановление пароля
├── ai-platforms.html              # защищённый интерфейс базы
├── assets/
│   ├── app.css                    # основной интерфейс
│   ├── app.js                     # каталог, сейф, аналитика, импорт/экспорт и синхронизация
│   ├── auth.css                   # оформление авторизации и статуса облака
│   ├── auth-page.js               # сценарии страницы входа
│   ├── route-guard.js             # проверка сессии и загрузка приложения
│   └── supabase-client.js         # клиент Supabase с publishable key
├── supabase/
│   ├── functions/                    # проверка доступа и защищённый вызов OpenAI
│   └── migrations/                   # хранилище, доступ, RLS и режим запуска
├── docs/                          # техническая документация
└── tools/                         # утилиты поэтапного обновления проекта
```

Приложение остаётся статическим и публикуется через GitHub Pages. Supabase отвечает за Auth, персональную облачную запись, тарифные права и Edge Functions. OpenAI API key хранится только в секретах Edge Function.

## Локальный запуск

Для проверки интерфейса нужен локальный HTTP-сервер: браузеры могут ограничивать модули и авторизацию при открытии через `file://`.

```bash
python3 -m http.server 8000
```

После запуска откройте `http://localhost:8000/`. Для полноценной авторизации localhost должен быть добавлен в разрешённые Redirect URLs проекта Supabase.
